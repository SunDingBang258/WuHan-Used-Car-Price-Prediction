### v1 → v2 改了什么

两处清洗改动 + 一处计算口径的变化：

**① 车系名称规范化**

同一个 `车系ID` 在原始数据里会有多种写法，例如 `揽胜极光进口` / `揽胜极光(进口)`。v1 保留了这些变体，导致 **475 个车系ID 对应 492 种名称**——ID 和名称不再一一对应。v2 对每个 `车系ID` 只保留出现次数最多的写法，收敛到 **279 种名称**。

为什么要做：`车系名称` 是应用做名称查表（`app/reference.json`）的键。不规范化的话用户在下拉框里会看到同一个车系的两个选项，查表也按名字走，同一台车的特征会被拆到两个"车系"里各算各的统计量。

**② 分组过滤（`MIN_BRAND=5` / `MIN_SERIES=3`，定点迭代到稳定）**

v1 保留了样本量很少的品牌和车系（共 475 个车系ID）。样本太少时，`品牌平均折价率` / `车系历史中位价` 这些统计量几乎就是这一两条车自己的值——**等于把目标泄漏进特征**。v2 把品牌 <5 条、车系 <3 条的组整组删掉，剩 279 个车系ID。

为什么 v2 行数反而更少：删掉了 267 条（占 7.8%）样本量不足的记录。

**③ 目标编码改用「过滤后」的行来算**

这一条不是新增的清洗步骤，而是 ② 带来的连带变化：

| | 算目标编码时用的行 |
|---|---|
| v1 | 全部 **3408** 行（v1 根本不做过滤）|
| v2 | 先过滤到 **3141** 行，**再**算 |

**为什么会不一样**：`品牌平均折价率` 是按品牌取中位数。v2 删掉的那 267 行虽然属于**被删掉的车系**，但它们的**品牌**还在（30 个品牌一个没少），所以它们**仍然会拉高/拉低该品牌的整体中位数**。

实测：**30 个品牌里有 21 个的值不同** ✗

| 品牌 | v1 里的品牌折价率 | v2 里的 | 差 |
|---|---|---|---|
| 领克 | 54.66% | **48.90%** | 5.76 |
| 长安 | 59.97% | **55.73%** | 4.24 |
| 奇瑞 | 60.09% | **63.04%** | 2.95 |
| 红旗 | 62.14% | **64.85%** | 2.71 |
| 宝马 | 71.75% | **69.80%** | 1.95 |
| 奔驰 | 66.42% | **64.59%** | 1.83 |

**车系级的两列不受影响**：两版共有的 278/279 个车系里，**一个值都没变** ✓
因为被删的 196 个车系是**整建制消失**，存活车系的行集合没变，中位数自然不变。

**为什么要纠正这个口径**：v1 的值是"还没过滤就算"的结果，而训练和应用需要的是
"按最终数据集算"的结果。旧版 v2 犯的正是这个错（先算再过滤），导致
CSV / `reference.json` 里存的值和训练时用过滤后数据重算的值不一致——
也就是 train/serve skew。现在 v2 改成了先过滤再算 ✓

## 生成命令

```powershell
.\.venv\Scripts\python.exe ml\data_pipeline.py
```

这一条命令做两件事：

1. 合并 / 清洗 / 补派生列 / 组过滤 → 再补三个目标编码特征 → 写出 `data/che168_wuhan_cars.csv`
2. 顺手导出 `app/reference.json`（品牌/车系 → ID + 查表特征），供应用的表单下拉和提交查表使用

> 顺序不能颠倒：`app/reference.json` 是这一步的产物，不是独立脚本生成的。

> ⚠️ 三个目标编码特征（两张折价率 + 车系中位价）必须在**组过滤之后**才算。
> 否则被过滤删掉的那 267 行仍会参与中位数，导致 CSV / `reference.json` 里存的值
> 和训练时用过滤后数据重算的值不一致（实测 21/30 个品牌有差异，最大 5.76 个百分点），
> 也就是 train/serve skew。

`售价(万元)` —— 回归目标。

### 仅展示（不参与训练）

`车源ID`、`详情页`、`车型`、`品牌名称`、`车系名称`、`新车指导价(万元)`、`封面图`

其中 `新车指导价` 值得说明：它有 1.3% 缺失，且实测**用它会掉到 63% MAPE**（因为指导价跨代差异大，不如车系历史中位价直接），所以只作展示。

## 清洗规则

按顺序执行，共删掉 987 条（23.9%）：

| 规则 | 删掉 | 理由 |
|---|---|---|
| 按 `车源ID` 去重 | 合并 906 条入 A | A 的品牌名权威，优先保留 |
| `品牌名称` 或 `车龄(年)` 为空 | **-712** | 这两列缺了没法用：品牌决定折价率，车龄是核心特征且年均里程依赖它 |
| `年均里程 > 10 万公里/年` | -1 | 物理矛盾（每天 274 公里全年无休），通常是上牌时间或里程录错 |
| 品牌样本 < 5 条 | 整组删 | 样本太少的组，算出来的「平均折价率」就是它自己 → 等于泄漏 |
| 车系样本 < 3 条 | 整组删 | 同上，中位价不可信 |

最后两条用**定点迭代**实现（反复过滤到稳定），因为删掉品牌会连带删掉它下面的车系：

```python
while True:
    size = len(merged)
    for key, least in (("品牌ID", MIN_BRAND), ("车系ID", MIN_SERIES)):
        counts = Counter(r[idx[key]] for r in merged)
        merged = [r for r in merged if counts[r[idx]] >= least]
    if len(merged) == size:
        break
```
